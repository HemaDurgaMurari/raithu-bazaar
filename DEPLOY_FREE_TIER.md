# Deploy Raithu Bazaar on the free tier

This setup uses one Render web service for the React website and Spring Boot API, plus Supabase for PostgreSQL. Free services have usage limits and may sleep or pause; this is suitable for a demo, not a reliability guarantee for a shop.

## 2. Create the Supabase database

Create a Supabase project and save its database password. In Supabase, find the direct PostgreSQL connection details in **Project Settings → Database → Connection string**. Configure Render with:

- `DATABASE_URL`: `jdbc:postgresql://<host>:5432/postgres?sslmode=require` (use the host shown by Supabase; keep SSL enabled)
- `DATABASE_USERNAME`: the database username shown by Supabase (commonly `postgres`)
- `DATABASE_PASSWORD`: the database password you set

If Supabase gives a pooler connection instead of a direct connection, use its host, port, and username exactly as displayed, add `jdbc:` before `postgresql://`, and preserve its SSL parameters.

## 3. Deploy the Blueprint

In Render, choose **New → Blueprint**, connect `HemaDurgaMurari/raithu-bazaar`, and deploy the `render.yaml` in the repository root. Render will request the database fields; enter the values above. `JWT_SECRET` is generated by the Blueprint. Keep all secrets in Render's dashboard.

After the deploy finishes, open the Render service URL. The site and its `/api` calls use the same origin. The Spring application creates/updates tables using Hibernate.

## Notes

- The free Render web service can spin down when idle and has limited CPU/RAM.
- Supabase free projects have database/storage limits and can pause after inactivity. Check current plan terms before relying on this for real orders.
- Render free Postgres is intentionally not used because it expires after 30 days.
- Email and Razorpay production credentials are not configured by this Blueprint. Add them as Render environment secrets only if those features are ready for production.
